## 📚 Contenido

### 1.3.1 Escenario 1 — Cadena Hotelera

> Las brechas de seguridad son cada vez más comunes, y los atacantes encuentran constantemente formas nuevas e innovadoras de infiltrarse en las organizaciones.

**¿Qué ocurrió?**

Una conocida cadena hotelera mundial sufrió una violación masiva de datos:

- Los hackers obtuvieron acceso a la base de datos de clientes usando **credenciales de un empleado**.
- Se expuso información personal de **más de 3 millones de huéspedes**.
- No se comprometieron contraseñas ni información financiera.

**¿Qué tomaron los hackers?**

| Dato robado | ¿Comprometido? |
|---|---|
| Nombres de huéspedes | ✅ Sí |
| Direcciones de correo electrónico | ✅ Sí |
| Números de teléfono | ✅ Sí |
| Contraseñas de cuentas | ❌ No |
| Información financiera | ❌ No |

> ⚠️ *Escenario ficticio con fines educativos.*

### 1.3.2 Escenario 2 — Plataforma de eLearning

**¿Qué ocurrió?**

Una popular plataforma de capacitación en línea dejó expuestos datos personales de millones de estudiantes (muchos menores de edad) en una **base de datos en la nube de acceso público**.

Los hackers accedieron directamente desde Internet a:

- 👤 Nombres completos
- 📧 Direcciones de correo electrónico
- 📞 Números de teléfono
- 🏫 Detalles de inscripción escolar

**¿Qué exploit utilizaron?**

> Los atacantes aprovecharon las **malas prácticas de seguridad** de la organización — específicamente, una base de datos en la nube sin protección expuesta a Internet.

Las organizaciones que migran a la nube sin asegurar correctamente sus recursos presentan **grandes vulnerabilidades** que los atacantes buscan activamente explotar.

---

### 1.3.3 Medidas Preventivas

¿Qué podrían haber hecho estas organizaciones para evitar las brechas?

| Medida | Descripción |
|---|---|
| 🎓 **Capacitación en ciberseguridad** | Entrenar a todo el personal para detectar y responder ante ciberataques |
| 🔐 **Autenticación de dos factores (2FA)** | Exigirla para acceder a archivos y aplicaciones con datos confidenciales |
| 📋 **Monitoreo continuo y logs** | Identificar comportamientos anómalos que indiquen una brecha |
| 🔑 **Hash + salting de contraseñas** | Almacenar contraseñas con algoritmos robustos de salado y hash |
| 🔒 **Segmentación de red** | Aislar recursos en la nube de la Internet pública en una red privada |
| 🌐 **Acceso solo por VPN** | Conceder acceso a datos y sistemas internos únicamente a través de VPN segura |

---

### 1.3.4 Conclusión clave

> Una **violación de la seguridad** es un incidente que provoca el acceso no autorizado a datos, aplicaciones, servicios o dispositivos, exponiendo información privada que los atacantes pueden usar para obtener beneficios económicos u otras ventajas.

Para protegerse:
- Mantenerse al tanto de las **ciberamenazas comunes**.
- Estar siempre **alerta** para no convertirse en la próxima víctima.
- Implementar un **plan de ciberseguridad integral** en la organización.

---

### 1.3.5 Investigación adicional (Lab)

Para profundizar, busca ejemplos reales de brechas de seguridad recientes y analiza:

1. 🤔 **¿Qué se llevaron?** — ¿Qué datos fueron comprometidos?
2. 🛠️ **¿Qué exploits usaron?** — ¿Cómo lograron el acceso?
3. 🛡️ **¿Cómo prevenirlo?** — ¿Qué medidas evitarían que ocurra de nuevo?

## 🧠 Términos clave

| Término | Definición |
|---|---|
| **Violación de seguridad** | Acceso no autorizado a datos, aplicaciones, servicios o dispositivos |
| **Exploit** | Técnica o vulnerabilidad utilizada por un atacante para comprometer un sistema |
| **Base de datos en la nube** | Almacenamiento de datos en servidores remotos accesibles por Internet |
| **Autenticación de dos factores (2FA)** | Método de verificación que requiere dos formas de identidad para acceder |
| **VPN** | Red privada virtual que cifra la conexión para proteger el acceso remoto |
| **Salting** | Técnica que añade datos aleatorios a una contraseña antes de aplicar el hash |
| **Hash** | Función que transforma datos en una cadena de longitud fija no reversible |
| **Segmentación de red** | División de una red en segmentos para limitar el acceso y reducir riesgos |
