## 📚 Contenido

### 2.3.1 Conceptos Clave

| Término | Definición |
|---|---|
| 🔍 **Vulnerabilidad** | Cualquier defecto en software o hardware que puede ser aprovechado |
| 💣 **Exploit** | Programa escrito específicamente para aprovechar una vulnerabilidad conocida |
| 🎯 **Ataque** | Uso de un exploit contra una vulnerabilidad para acceder a un sistema, sus datos o recursos |

---

### 2.3.2 Vulnerabilidades de Hardware

Surgen por **defectos de diseño** en el hardware. Son específicas de modelos de dispositivos y generalmente no son objetivo de ataques aleatorios.

#### 🔨 Rowhammer
- La **RAM** almacena datos en condensadores ubicados muy cerca entre sí.
- Al acceder repetidamente (*martillar*) a una fila de memoria, se generan interferencias eléctricas que **corrompen los datos** en filas vecinas.
- Esta falla de diseño de proximidad dio origen al exploit **Rowhammer**.

#### ❄️ Meltdown y Spectre

Descubiertas por investigadores de seguridad de **Google**; afectan a casi todas las CPUs lanzadas desde 1995.

| Vulnerabilidad | Impacto |
|---|---|
| **Meltdown** | Permite leer **toda la memoria** de un sistema |
| **Spectre** | Permite leer **datos manejados por otras aplicaciones** |

- Se clasifican como **ataques de canal lateral** (la información se obtiene de la implementación física del sistema).
- Pueden ejecutarse múltiples veces con muy pocas posibilidades de generar un error o bloqueo detectable.

> 🛡️ Para el usuario cotidiano, la **protección tradicional contra malware** y una **buena seguridad física** son suficientes frente a estas vulnerabilidades.

### 2.3.3 Vulnerabilidades de Software

Causadas por errores en el **sistema operativo** o en el **código de la aplicación**.

#### 📌 Caso real — SynFul Knock (Cisco IOS, 2015)

- Permitió a los atacantes tomar control de **enrutadores empresariales** de Cisco (ej. routers ISR).
- Desde allí podían **monitorear todas las comunicaciones de red** e infectar otros dispositivos.
- Se introdujo al instalar una **versión alterada del IOS** en los routers.
- **Prevención:** Verificar siempre la integridad de la imagen de IOS descargada y limitar el acceso físico al equipo solo a personal autorizado.

### 2.3.4 Categorías de Vulnerabilidades de Software

| Categoría | Descripción | Ejemplo en @Apollo |
|---|---|---|
| 📦 **Desbordamiento de búfer** | Los datos se escriben más allá de los límites de memoria asignados, pudiendo causar bloqueos, corrupción de datos o escalada de privilegios | — |
| ✏️ **Entrada no validada** | El programa acepta datos maliciosos que lo obligan a comportarse de forma no deseada | Usuarios que inician sesión con dirección de correo con formato incorrecto |
| 🏁 **Condiciones de carrera** | La salida depende de eventos cronometrados que no ocurren en el orden correcto | — |
| 🔑 **Debilidad en prácticas de seguridad** | Uso inadecuado de autenticación, autorización o cifrado; o intento de crear algoritmos propios sin pruebas | Contraseñas enviadas por correo en texto sin formato sin solicitar cambio |
| 🚧 **Problemas de control de acceso** | Uso incorrecto de controles sobre quién accede a qué recursos y qué puede hacer con ellos | Exempleados con acceso activo a la base de datos de clientes |

> ⚠️ **Importante:** Casi todos los controles de acceso pueden ser **superados con acceso físico** al equipo. El cifrado y la restricción de acceso físico son esenciales.

### 2.3.5 Actualizaciones de Software y Gestión de Vulnerabilidades

- **Microsoft, Apple** y otros fabricantes lanzan parches y actualizaciones casi todos los días.
- Nuevas vulnerabilidades se descubren continuamente, a pesar de los esfuerzos de corrección.

**Estrategias de las organizaciones para gestionar vulnerabilidades:**

| Estrategia | Descripción |
|---|---|
| 🔍 **Investigadores de terceros** | Especialistas externos que buscan vulnerabilidades en el software |
| 🛠️ **Equipos de penetración internos** | Equipos dedicados a buscar y parchear vulnerabilidades antes de que sean explotadas |
| 🌐 **Project Zero (Google)** | Equipo permanente de Google dedicado a encontrar vulnerabilidades en software de uso masivo |

> 📎 Más información sobre Project Zero: [bugs.chromium.org/p/project-zero](https://bugs.chromium.org/p/project-zero/issues/list?can=1&redir=1)

### 2.3.6 Identificación de Vulnerabilidades — Casos Prácticos @Apollo

| Escenario | Categoría |
|---|---|
| La contraseña de red fue enviada por correo en texto sin formato sin solicitar cambio | 🔑 Debilidad en prácticas de seguridad |
| Exempleados aún tienen acceso a la base de datos de clientes | 🚧 Problemas de control de acceso |
| Usuarios pueden registrarse con una dirección de correo con formato incorrecto | ✏️ Entrada no validada |

## 🧠 Términos clave

| Término | Definición |
|---|---|
| **Vulnerabilidad** | Defecto en hardware o software que puede ser aprovechado por un atacante |
| **Exploit** | Programa diseñado para aprovechar una vulnerabilidad específica |
| **Rowhammer** | Exploit que corrompe datos en RAM mediante accesos repetidos a filas de memoria |
| **Meltdown** | Vulnerabilidad de CPU que permite leer toda la memoria del sistema |
| **Spectre** | Vulnerabilidad de CPU que permite leer datos de otras aplicaciones |
| **Ataque de canal lateral** | Ataque que obtiene información de la implementación física de un sistema |
| **Desbordamiento de búfer** | Escritura de datos más allá de los límites de memoria asignados |
| **Escalada de privilegios** | Obtención de acceso a recursos normalmente restringidos |
| **Parche** | Actualización de software que corrige una vulnerabilidad conocida |
| **Prueba de penetración** | Simulación de ataques para encontrar y corregir vulnerabilidades antes de que sean explotadas |
